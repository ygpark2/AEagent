aeagent TODO
============

Completed in current implementation
-----------------------------------
- Added durable workflow definitions via agent_workflows.
- Added execution timeline events via agent_execution_events.
- Added durable human approval queue via agent_approval_requests.
- Added approval API:
  - GET /api/v1/approvals
  - GET /api/v1/approvals/:id
  - POST /api/v1/approvals/:id/approve
  - POST /api/v1/approvals/:id/reject
- Added dashboard Approvals tab for pending durable approval requests.
- Added DB-backed MCP/tool registry via agent_tool_registry.
- Added tool registry API:
  - GET /api/v1/tools/registry
  - POST /api/v1/tools/registry/sync
  - PATCH /api/v1/tools/registry/:server_id/:tool_name
- Connected registry metadata to tool permission/risk/confirmation/retry/timeout behavior.
- Added policy decision trace:
  - New AOS.AgentOS.Core.PolicyTrace persists allow/blocked/pending decisions to
    agent_execution_events as "policy.allowed" / "policy.blocked" / "policy.pending".
  - PolicyGate now traces every SafetyPolicy/BudgetPolicy/DomainPolicy check (per-policy,
    stops recording once one halts execution, matching PolicyGate's own short-circuit).
  - ApprovalService now traces tool-allowlist decisions (skill permission, autonomy level,
    auto-approve) and approval-check decisions (previously-approved, durable pending,
    interactive approve/reject), tagged "ToolAllowlist" / "ApprovalCheck".
  - Each event payload carries policy name, decision, reason, node_id/tool_name, and an
    input_summary (domain, autonomy_level, loop_count, cost_usd for PolicyGate).
  - Already surfaced in the replay payload for free (Executions.replay_execution/1 lists
    all agent_execution_events) - no replay code change needed.
  - Event.changeset now declares foreign_key_constraint/2 for execution_id/session_id/
    workflow_id, and EventStore.append_event/1 rescues Ecto.ConstraintError, since the
    SQLite adapter can't map its FK violation to a named constraint and raises instead of
    returning a changeset error - timeline events are best-effort and must never crash the
    caller (e.g. ApprovalService's approved-request lookup, which intentionally probes with
    a not-yet-persisted execution_id).
  - Tests: test/aos/agent_os/core/policy_gate_test.exs,
    test/aos/agent_os/tool_use/approval_service_test.exs, plus a replay assertion in
    executions_test.exs.
- Added unified execution timeline UI:
  - New "Timeline" tab on the agent dashboard (lib/aos_web/live/agent_dashboard_live.ex/.heex),
    alongside Inspection/Settings/Approvals.
  - DashboardService.timeline_entries/1 merges agent_execution_events (execution.*,
    approval.*, policy.* - all of it, via Executions.replay_execution/1), tool audits, and
    delegation traces into one list, sorted ascending by timestamp.
  - Each entry carries a category (event/tool/delegation), a badge, a human title (approval
    and policy events surface tool_name/policy/reason in the title), an optional subtitle,
    and a timestamp.
  - Dashboard now tracks a `current_execution_id` assign (set when a chat message enqueues a
    new execution) and a `timeline_entries` assign, refreshed on tab switch and after
    workflow_error/execution_terminal/tool-confirmation-request/durable-approval-decision
    events while the Timeline tab is active.
  - Tests: test/aos/agent_os/dashboard_service_test.exs (entry merging/ordering/titles),
    plus a LiveView test for the empty state in test/aos_web/live/agent_dashboard_live_test.exs.
  - Verified by hand: ran the dev server, logged in, confirmed /agent renders with the new
    Timeline button server-side (curl), matching the same "only the active tab's body
    renders" behavior as the existing Settings/Approvals tabs. A full interactive
    click-through wasn't done (no browser automation available in this environment) - the
    LiveViewTest suite exercises the same mount/handle_event/render code path a browser
    would, but a manual click-through in a real browser is still worth doing before calling
    this fully done.
  - Not done: no historical-execution picker - the tab always shows the most recently
    enqueued execution in the current dashboard session, not older ones.

Next high-priority work
-----------------------
1. Approval resume hardening
   - Store the blocked node/checkpoint when approval is requested.
   - Resume from the last stable checkpoint instead of rebuilding from broad execution context only.
   - Add explicit resume mode for approval continuation.
   - Avoid duplicate pending approval requests for identical unresolved tool calls.

2. Tool registry health checks
   - Add health check behavior for internal and external MCP tools.
   - Store last_health_check_at and health_status transitions.
   - Automatically mark external MCP tools unavailable when server calls fail repeatedly.
   - Add registry health endpoint and dashboard status.

3. Tool registry allowlists and scopes
   - Add workflow/session-level tool allowlists.
   - Add registry scopes/capabilities such as file_read, file_write, shell_exec, web_search, web_fetch.
   - Make skill permissions resolve through registry capabilities instead of only static config.
   - Add path/domain constraints for tools that access files or network.

4. Workflow definition runner
   - Use stored Workflow.graph/policy_profile/approval_policy at runtime.
   - Add create/update/list/show workflow API.
   - Add dashboard/admin view for workflow definitions.
   - Add trigger definitions for manual, webhook, Slack, and scheduled runs.

5. Durable execution improvements
   - Add pause/cancel/resume API.
   - Add stuck execution detector.
   - Add idempotency keys for tool calls and LLM calls.
   - Persist node transitions before and after each node execution.
   - Add explicit timeout handling for workflow and node execution.

6. Agent contract validation
   - Define AgentContract with input_schema, output_schema, allowed_tools, success_criteria, max_turns.
   - Validate worker/evaluator/delegator outputs against schemas.
   - Record contract violations as execution events.
   - Use contract failures to decide retry, delegation, or blocking.

7. Metrics and evaluation loop
   - Track workflow success rate, approval rate, rejection rate, tool failure rate, retry count, latency, and cost.
   - Feed these metrics into strategy evaluation.
   - Add dashboard cards for operational metrics.
   - Add API endpoint for workflow/tool performance summaries.

8. API and dashboard polish
   - Add OpenAPI/Swagger definitions for approvals, workflows, registry, and timeline endpoints.
   - Add pagination/filtering for approval and registry APIs.
   - Add audit-friendly display of actor identity for approval decisions.
   - Add tests for error cases and permission failures.
