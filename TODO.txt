aeagent TODO
============

Completed in current implementation
-----------------------------------
- Added durable workflow definitions via agent_workflows.
- Added execution timeline events via agent_execution_events.
- Added durable human approval queue via agent_approval_requests.
- Added approval API:
  - GET /api/v1/approvals
  - GET /api/v1/approvals/:id
  - POST /api/v1/approvals/:id/approve
  - POST /api/v1/approvals/:id/reject
- Added dashboard Approvals tab for pending durable approval requests.
- Added DB-backed MCP/tool registry via agent_tool_registry.
- Added tool registry API:
  - GET /api/v1/tools/registry
  - POST /api/v1/tools/registry/sync
  - PATCH /api/v1/tools/registry/:server_id/:tool_name
- Connected registry metadata to tool permission/risk/confirmation/retry/timeout behavior.
- Added policy decision trace:
  - New AOS.AgentOS.Core.PolicyTrace persists allow/blocked/pending decisions to
    agent_execution_events as "policy.allowed" / "policy.blocked" / "policy.pending".
  - PolicyGate now traces every SafetyPolicy/BudgetPolicy/DomainPolicy check (per-policy,
    stops recording once one halts execution, matching PolicyGate's own short-circuit).
  - ApprovalService now traces tool-allowlist decisions (skill permission, autonomy level,
    auto-approve) and approval-check decisions (previously-approved, durable pending,
    interactive approve/reject), tagged "ToolAllowlist" / "ApprovalCheck".
  - Each event payload carries policy name, decision, reason, node_id/tool_name, and an
    input_summary (domain, autonomy_level, loop_count, cost_usd for PolicyGate).
  - Already surfaced in the replay payload for free (Executions.replay_execution/1 lists
    all agent_execution_events) - no replay code change needed.
  - Event.changeset now declares foreign_key_constraint/2 for execution_id/session_id/
    workflow_id, and EventStore.append_event/1 rescues Ecto.ConstraintError, since the
    SQLite adapter can't map its FK violation to a named constraint and raises instead of
    returning a changeset error - timeline events are best-effort and must never crash the
    caller (e.g. ApprovalService's approved-request lookup, which intentionally probes with
    a not-yet-persisted execution_id).
  - Tests: test/aos/agent_os/core/policy_gate_test.exs,
    test/aos/agent_os/tool_use/approval_service_test.exs, plus a replay assertion in
    executions_test.exs.
  - Not done yet: no dashboard UI renders these events - that's covered by item 1 below
    (Unified execution timeline UI), which doesn't exist in the dashboard yet at all.

   - Render approval.requested / approval.approved / approval.rejected events.
   - Render tool audit summaries and delegation traces in chronological order.

2. Approval resume hardening
   - Store the blocked node/checkpoint when approval is requested.
   - Resume from the last stable checkpoint instead of rebuilding from broad execution context only.
   - Add explicit resume mode for approval continuation.
   - Avoid duplicate pending approval requests for identical unresolved tool calls.

3. Tool registry health checks
   - Add health check behavior for internal and external MCP tools.
   - Store last_health_check_at and health_status transitions.
